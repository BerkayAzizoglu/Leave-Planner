## Project Overview

**Smart Leave Planner** is an intelligent productivity app that helps users maximize their annual leave efficiency by combining public holidays, company holidays, and leave balance to generate optimized vacation opportunities. It surfaces the best opportunities automatically — e.g. *"Use 3 days of leave to get 9 days off"*.

**Stack:** Next.js 16 (App Router) · TypeScript · Tailwind CSS v4 · Zustand · Framer Motion · date-fns · Lucide React

## Architecture

### State Management (`lib/store.ts`)
Zustand store with `persist` middleware (localStorage key: `leave-planner-store`). Persisted state: `profile` and `selectedYear`. Ephemeral state: `publicHolidays`, `optimizations`.

Key state shape:
```ts
{
  profile: UserProfile        // All user config (country, balance, holidays, etc.)
  publicHolidays: Holiday[]   // Fetched from Nager.Date API
  optimizations: LeaveOptimization[]  // Generated by optimizer
  selectedYear: number
}
```

### Holiday Fetching (`lib/holidays.ts`)
- Calls `https://date.nager.at/api/v3/PublicHolidays/{year}/{countryCode}`
- In-memory cache per `{country}-{year}` key to avoid re-fetching
- Falls back to a minimal hardcoded set if the API is unreachable

### Leave Optimization Algorithm (`lib/optimizer.ts`)
The core algorithm scans every working day of the year and identifies "bridge" windows — contiguous working day blocks surrounded by non-working days (weekends + holidays). For each such block:
1. Calculates efficiency ratio: `totalDaysOff / leaveDaysNeeded`
2. Filters blocks where ratio ≥ 1.8
3. Classifies into types: `long-weekend`, `bridge`, `cluster`, `week-stretch`
4. Deduplicates overlapping windows (greedy, highest efficiency first)
5. Returns up to 12 top opportunities

### Travel Data (`lib/travel.ts`)
Static curated dataset of ~18 destinations and 10 local activities. Destinations are tagged with `regions[]` (europe, americas, turkey, asia) to match the user's country region. Filtered by budget level and category at render time.

## Design System

### Color Palette (Tailwind v4 CSS `@theme` tokens)
```
beige-50  #FAFAF7   (page background)
beige-100 #F5F0E8   (card borders, dividers)
sage-*    greens    (primary — leave, holidays, CTAs)
sky-*     blues     (secondary — stats, company holidays)
coral-*   warm red  (blocked dates, week-stretch type)
amber-*   yellow    (school holidays, cluster type)
```

### Typography
System font stack via CSS variable `--font-sans`. No Google Fonts (network not available in build environment).

### Motion
Framer Motion used for:
- Page element stagger animations (`container` / `item` variants)
- Expand/collapse accordion sections (`AnimatePresence` + height animation)
- Tap feedback (`whileTap: { scale: 0.98 }`)
- Onboarding step transitions (`AnimatePresence mode="wait"`)

### Mobile-First
App is designed as a mobile web app (max-width 448px centered). Bottom navigation is fixed with `safe-bottom` padding for iOS home indicator.

## Adding Features

### New supported country
1. Add to `COUNTRIES` array in `lib/countries.ts`
2. Nager.Date will handle holidays automatically if the country code is valid

### New travel destinations
Add to the `DESTINATIONS` array in `lib/travel.ts`. Include appropriate `regions[]` tags.

### New optimization strategy
Extend the algorithm in `lib/optimizer.ts`. The main loop in `generateOptimizations()` processes working day blocks — add new pattern detection there.

### New screen
1. Create `app/<route>/page.tsx` (add `'use client'` if using hooks/state)
2. Add to `tabs` array in `components/Navigation.tsx`

## Conventions

### File naming
- Pages: `app/<route>/page.tsx`
- Components: PascalCase in `components/`
- Lib utilities: camelCase in `lib/`

### `'use client'` directive
Required on any component that uses: React state, hooks, Zustand store, Framer Motion, browser APIs, event handlers. NOT needed on pure display server components.

### Styling approach
Use inline `style={{ }}` for dynamic colors (from theme constants). Use Tailwind classes for layout, spacing, and static styles. Avoid mixing arbitrary Tailwind values with the design system tokens — use the CSS variables defined in `globals.css @theme`.

### No API keys required
Do not add features requiring paid APIs or secrets without explicit discussion. Keep the app self-contained and deployable without configuration.

## Dos and Don'ts for AI Assistants

### Do
- Read files before editing
- Run `npm run build` after changes to catch TypeScript errors early
- Keep the optimization algorithm pure (no side effects, fully testable)
- Follow the established component patterns (motion.div, style props for colors)
- Update this `CLAUDE.md` when significant architecture changes are made

### Don't
- Add Google Fonts (blocked in this build environment — use system font stack)
- Introduce API keys or `.env` secrets
- Use `any` types — the codebase is fully typed
- Force-push to `main` without permission
- Import from `next/font/google` (see layout.tsx)
